Towards automating formal cryptographic proofs

Our vision: formal cryptographic proofs should keep pace with cryptographic innovation. We are working toward a future where cryptographers can explore and verify security arguments earlier and faster, without compromising the rigor of machine checking.
You supply the scheme, security assumptions, and final theorem in EasyCrypt. Shannon Prover searches for the intermediate games and auxiliary lemmas, writes their proofs, and checks the complete development with EasyCrypt.

Where Shannon Prover fits

Shannon Prover automates proof construction across Phases II and III. Earlier Shannon workflows proved individual lemmas supplied by a human. Shannon can now also propose and revise the decomposition of the security argument. You still provide the formal security model and theorem in Phase I.

How Shannon Prover builds a security proof

A proof rarely develops in a straight line. Shannon may propose a game hop, try to prove the required equivalence, and discover that an auxiliary lemma needs a stronger invariant. It can revise that lemma and return to the overall argument. This feedback between designing the argument and proving its steps is what we mean by interleaved.

Build the argument
Choose games and lemmas
One agent develops the overall proof and identifies the intermediate claims it needs.
Prove the steps
Write EasyCrypt proofs
It works directly and can ask other agents to prove selected auxiliary lemmas.
Learn from the attempt
Revise the argument
Checked steps and remaining goals inform the next proof attempt or a revised decomposition.
Check the result
Verify the complete file
EasyCrypt checks the assembled development; unfinished proofs do not count as success.

Shannon is a research prototype: an attempt may finish with a checked proof, partial work, or no proof within the time limit. Review that the generated statements and assumptions match your intended security claim. The generic checker does not freeze those inputs; the supplied ChaChaPoly example adds checks that preserve its fixed problem.

Follow the project-level proving guide to prepare a project and interpret the results. The proof browser below shows individual lemma attempts, not a complete interleaved run.

What an EasyCrypt proof looks like

Given a lemma, an EasyCrypt proof is a sequence of tactics that transforms its current goal until no obligations remain. Here is a complete four-tactic example from the public MEE-CBC development in this repository.

eval/examples/MEE-CBC/CBC.ecaDQ_Sample_Compute_pr
lemma
local lemma DQ_Sample_Compute_pr &m:
  Pr[INDR_CPA_direct(CBC_Oracle(DoubleQuery(Sample)),A).main() @ &m:
     DoubleQuery.bad] =
  Pr[INDR_CPA_direct(Compute,A).main() @ &m : Compute.bad]
proof
proof.  byequiv=> //=.  proc; call (_: ={bad,qs}(DoubleQuery,Compute)).  by conseq DQ_Sample_Compute_eq.  by inline *; auto.qed.
1After byequiv=> //=.
pre = (glob A){2} = (glob A){m} /\ (glob A){1} = (glob A){m} INDR_CPA_direct(CBC_Oracle(DoubleQuery(Sample)), A).main ~ INDR_CPA_direct(Compute, A).main post = DoubleQuery.bad{1} = Compute.bad{2}
2After by inline *; auto.
No more goals

The proof is shown exactly from proof. to qed.. The numbered highlights match the EasyCrypt goals shown after those steps. Long lines wrap to fit.

How the LLM interacts with EasyCrypt

For each lemma, the agent sees what EasyCrypt still needs to prove, tries a proof step, and reads the resulting goals or error. It can continue, undo a step, or try another approach.

Executes tactics and returns the resulting goal or error. Only checker-accepted steps enter the proof.

The agent can consult the allowed EasyCrypt source declarations as it works. EasyCrypt remains responsible for interpreting and checking the mathematics. Before a result is accepted, the proof is checked again independently of the interactive attempt.

You need macOS or Linux, Git, opam, Python ≥ 3.12, uv, and the agent CLIs you select. For project-level proving, the defaults use Claude Code for the overall argument and Codex for auxiliary lemmas, with their stored Claude and ChatGPT OAuth logins. Steps 1–2 install the shared tools; steps 3–4 launch a Phase II + III proof.

Set up the repository

git clone https://github.com/SkyShannonProver/shannon-prover.git
cd shannon-prover
uv sync

Install the locked EasyCrypt toolchain

Shannon Prover is locked to EasyCrypt r2026.06. The bootstrap command creates and verifies the repository-managed opam root and switch:

uv run python tools/bootstrap_easycrypt.py
uv run python tools/bootstrap_easycrypt.py --verify-only

Python entry points select this environment automatically; no ambient opam switch is required.

Choose the project's final security theorem

Create one directory under projects/ with your security model, final theorem, and local dependencies. Leave the target theorem's proof unfinished. Add interleaved_project.json using the project setup guide, then commit these files so the checkout is clean.

projects/
  my-proof/
    Target.ec
    Dependency.ec
    interleaved_project.json

Start a project proof — Phases II + III

From a terminal at the repository root, first check the setup without starting a proof-generating model:

uv run python -m workflow.interleaved \
  --project projects/my-proof/interleaved_project.json \
  --preflight-only

Once these pass, start the proof attempt:

uv run python -m workflow.interleaved \
  --project projects/my-proof/interleaved_project.json

This run works toward the final theorem named in your configuration and constructs the auxiliary lemmas it needs. To use Codex in both roles, add --outer-provider codex --inner-provider codex to both commands.

Good to know
  • Set the time limits before running. The example allows two auxiliary lemmas at once, up to two hours per attempt, and twelve hours overall. These limits are not a total spending cap.
  • Read the final result. A successful project-level run records status: "proved" and final_verification_passed: true in manifest.json. A verified auxiliary lemma alone is not the final theorem.
  • Review the generated changes. Shannon Prover edits your target during its attempt. Check that the final statements and assumptions express the security claim you intended.

Single-lemma proving — Phase III

After the shared installation in steps 1–2, put your EasyCrypt file and local dependencies under projects/, leaving the selected lemma's proof unfinished. Open Codex or Claude Code from the repository root and enter one of these commands inside that agent:

# In Codex
$prove my_lemma

# In Claude Code
/prove my_lemma

Replace my_lemma with the declaration's name. These commands target that one lemma; they do not launch the Phase II + III project workflow or require interleaved_project.json. The generated proof is written back only after EasyCrypt verification succeeds.

See the single-lemma proving guide for an example.
